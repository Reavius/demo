# «Мечты» — серверная версия сайта и Telegram-бронирование

Это не статический архив для обычного хостинга HTML-файлов: здесь нужен постоянно работающий Node.js-сервер (или Docker-хостинг с постоянным диском). В этой сборке сайт и `/admin.html` используют один серверный API. Заявки, афиша, меню, залы и другие правки сохраняются в `DATA_DIR/store.json`, а не в LocalStorage браузера. Фото из админки сохраняются в `uploads/`.

## Что умеет Telegram-бот

- Гость запускает бота командой `/start` и проходит оформление брони: зал → дата → время → количество гостей → имя → телефон → комментарий → согласие на обработку персональных данных.
- Новая заявка сохраняется в том же общем хранилище, что и брони с сайта.
- Администратор получает сообщение в Telegram с кнопками «Подтвердить» и «Отменить».
- После решения администратора гость, оформивший бронь через Telegram, получает сообщение о результате.
- Команда `/id` показывает ID чата для настройки уведомлений.
- Команда `/cancel` прерывает оформление заявки.

## Требования

- Node.js 22 или новее.
- Один постоянно работающий Node.js процесс.
- HTTPS для публичного сайта и Telegram API.
- Постоянное дисковое хранилище для `DATA_DIR` и `UPLOAD_DIR`.

## Запуск на сервере

1. Скопируйте файлы проекта на сервер.
2. Создайте `.env` на основе `.env.example`.
3. Установите длинный уникальный `ADMIN_PASSWORD` (минимум 14 символов).
4. Создайте Telegram-бота через `@BotFather` командой `/newbot` и добавьте токен в `TELEGRAM_BOT_TOKEN`.
5. Укажите username бота (без `@`) в `TELEGRAM_BOT_USERNAME`, чтобы на сайте появилась кнопка бронирования через Telegram.
6. Запустите сервер: `npm start`.
7. Откройте личный чат с ботом и отправьте `/id`. Скопируйте `chat_id` в `TELEGRAM_ADMIN_CHAT_IDS` на сервере и перезапустите приложение.
8. Заполните шаблон `privacy.html` реальными реквизитами оператора, юридическим адресом, сроком хранения данных и почтой; после проверки установите `PERSONAL_DATA_READY=true`. Пока флаг `false`, сайт и бот не принимают новые заявки.
9. После публикации сайта укажите его полный HTTPS-адрес в `PUBLIC_SITE_URL`, чтобы бот мог дать гостю прямую ссылку на политику конфиденциальности.
10. Откройте `/admin.html`, войдите с `ADMIN_PASSWORD` и проверьте создание тестовой брони.

Для нескольких администраторов укажите несколько ID через запятую, например `TELEGRAM_ADMIN_CHAT_IDS=123456789,987654321`.

## Важные настройки размещения

- Настройте постоянный диск и укажите на нём `DATA_DIR` и `UPLOAD_DIR` (например, `/var/lib/mechty` и `/var/lib/mechty/uploads`). Без постоянного диска данные и загруженные изображения могут пропасть после пересоздания контейнера.
- Запускайте только один экземпляр приложения: это хранилище рассчитано на один Node.js процесс/инстанс. Не включайте несколько worker-процессов.
- Настройте HTTPS и проксирование домена на порт приложения. При доверенном reverse proxy установите `TRUST_PROXY=1`; не открывайте внутренний порт приложения напрямую в интернет. Не публикуйте `.env`, каталог `data/` или исходники сервера.
- Сделайте регулярные резервные копии `DATA_DIR/store.json` и каталога `UPLOAD_DIR`.
- Токен Telegram и пароль администратора храните в переменных окружения хостинга, а не в Git или в публичной папке сайта.

## Перед реальным приёмом заявок

При `PERSONAL_DATA_READY=false` сервер блокирует отправку новых заявок с сайта и из Telegram. Включайте приём только после заполнения политики и проверки реальных реквизитов.

Данные из прежнего браузерного демо автоматически не переносятся: они хранились локально на отдельных устройствах.

В `privacy.html` исходного проекта пока есть шаблонные поля: наименование/ИНН оператора, юридический адрес, срок хранения заявок и контактная почта. Заполните их реальными данными и согласуйте текст с ответственным за персональные данные/юристом до публикации. Не заменяйте эти поля вымышленными значениями.

## Локальная проверка

```bash
cp .env.example .env
# Для локальной проверки без HTTPS в .env поставьте:
# NODE_ENV=development
# TRUST_PROXY=0
# задайте ADMIN_PASSWORD (минимум 14 символов)
npm test
npm start
```

Проверка доступности сервера: `GET /healthz`.
